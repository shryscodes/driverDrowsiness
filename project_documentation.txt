PROJECT PURPOSE
---------------
This project is a camera-based Driver Drowsiness Detection System.

Its purpose is to monitor a driver's face using a webcam and detect
possible signs of drowsiness using:

1. Eye closure / EAR
2. Yawning / MAR
3. Head tilt / head roll angle
4. Time-based persistence of these conditions
5. Audible alarm

The project is being built modularly. Each feature is implemented and
tested separately before the modules are integrated into main.py.

-------
Purpose:
Calculates Eye Aspect Ratio (EAR).

The eye landmark points are used to calculate vertical and horizontal

calibration.py
--------------
Purpose:
Personalizes the eye-closure threshold for the current driver.

Calibration process:
1. Camera opens.
2. Face landmarks are detected.
3. Eye landmarks are extracted.
4. EAR is calculated for both eyes.
5. Average EAR is collected over approximately 5 seconds.
6. Median EAR becomes the natural open-eye baseline.
7. Standard deviation is calculated.
8. A personalized eye-closure threshold is calculated.

Current threshold formula:

    threshold = baseline_EAR * 0.70

Example calibration obtained during development:

    Measurements collected : 136
    Open-eye baseline EAR  : 0.335
    EAR standard deviation : 0.016
    Eye-closure threshold  : 0.234

Another complete-system calibration produced:

    Open-eye baseline EAR  : 0.319
    EAR standard deviation : 0.014
    Eye-closure threshold  : 0.223

The exact values change between calibrations because the system
personalizes the threshold using live camera measurements.

IMPORTANT:
Calibration should be performed with the driver's eyes naturally open
and the face looking approximately straight at the camera.

yawn_detector.py
----------------
Purpose:
Detects yawning using Mouth Aspect Ratio (MAR).

The mouth landmarks are used to calculate how open the mouth is.

A yawn is not triggered from one frame alone. The mouth must remain
above the configured MAR threshold for the required duration.

A previously tested configuration used approximately:

    MAR threshold = 0.42
    Yawn duration = 1.0 second

These values are prototype values and can be tuned after testing.


head_pose.py
------------
Purpose:
Detects left/right head tilt using the relative positions of the eyes.

The current module calculates the angle of the line joining the eye
centers.

IMPORTANT PROBLEM FOUND:
The original implementation could report approximately 180 degrees
when the head was actually straight. This happened because atan2()
can represent a horizontal line as either approximately 0 degrees
or approximately 180 degrees depending on vector orientation.

The corrected approach normalizes the angle so:

    Straight head -> approximately 0 degrees

The current normalization logic is conceptually:

    if angle > 90:
        angle -= 180

    elif angle < -90:
        angle += 180

This converts the angle into approximately:

    -90 <= angle <= +90

A straight head should normally fluctuate around 0 degrees rather than
180 degrees.

Current prototype configuration:

    Head tilt threshold = 15 degrees
    Head tilt duration  = 1.5 seconds

The duration prevents brief movements from immediately being classified
as a sustained head-tilt event.

======================================================================
3. IMPORTANT FORMULAS
======================================================================

A. EYE ASPECT RATIO (EAR)
-------------------------

EAR is used to estimate how open an eye is.

For six eye landmarks:

    EAR = [ ||p2-p6|| + ||p3-p5|| ]
          ---------------------------
                 2 * ||p1-p4||

Where:

p1 and p4 are the left/right horizontal eye points.

p2, p3, p5 and p6 are the vertical eye points.

Equivalent form:

    EAR = (vertical_distance_1 + vertical_distance_2)
          --------------------------------------------
                  2 * horizontal_distance

Interpretation:

- Open eye -> relatively larger EAR
- Closed eye -> much smaller EAR

The exact EAR value depends on camera position, face geometry,
landmark quality, and individual driver characteristics.

That is why the project performs personalized calibration.


B. MOUTH ASPECT RATIO (MAR)
---------------------------

MAR is used to estimate mouth opening.

The general concept is similar to EAR:

    MAR = sum of vertical mouth distances
          --------------------------------
             horizontal mouth distance

A larger MAR indicates a more open mouth.

A sustained large MAR can indicate yawning.

Prototype configuration used:

    MAR threshold = 0.42
    Duration      = 1.0 second

These are adjustable experimental parameters.


C. HEAD ROLL / TILT ANGLE
-------------------------

The eye centers are first calculated.

Let:

    Left eye center  = (Lx, Ly)
    Right eye center = (Rx, Ry)

Then:

    dx = Rx - Lx
    dy = Ry - Ly

The raw eye-line angle is:

    angle = atan2(dy, dx) * 180 / pi

The raw result can be near 180 degrees even when the head is
actually straight.

Therefore, normalize it:

    if angle > 90:
        angle = angle - 180

    elif angle < -90:
        angle = angle + 180

Result:

    approximately -90 degrees <= angle <= +90 degrees

Straight head:
    approximately 0 degrees

Tilted left/right:
    negative/positive angle depending on image coordinate direction.

4. CURRENT DETECTION LOGIC
======================================================================

EYE CLOSURE
-----------

1. Calculate EAR every frame.
2. Compare EAR with personalized threshold.
3. If EAR stays below the threshold long enough, classify as
   prolonged eye closure/drowsiness.
4. A normal short blink should not trigger the alarm.

Current prototype configuration:

    Eye closure threshold:
        personalized from calibration

    Eye closure duration:
        2.0 seconds

Concept:

    if EAR < threshold:
        start/continue closure timer

    if closure_time >= 2 seconds:
        drowsiness event


YAWNING
-------

1. Calculate MAR.
2. If MAR exceeds the yawn threshold, start/continue a timer.
3. If it remains above threshold long enough, report a yawn.

Current prototype:

    MAR threshold = 0.42
    Yawn duration = 1.0 second


HEAD TILT
---------

1. Calculate roll angle from eye centers.
2. Normalize the angle around 0 degrees.
3. Compare absolute angle with threshold.
4. Require the tilt to persist for the configured duration.

Current prototype:

    Tilt threshold = 15 degrees
    Tilt duration  = 1.5 seconds

Concept:

    if abs(angle) >= 15:
        start/continue tilt timer

    if tilt_duration >= 1.5 seconds:
        head tilt event


ALARM
-----

The alarm should not be triggered simply because one frame is
abnormal.

It should respond to the project's event logic.

Current Alarm API:

    alarm.start()

    alarm.stop()

The alarm runs repeated warning beeps in a background thread.

11. MULTI-FACTOR DROWSINESS LOGIC - FUTURE DESIGN
======================================================================

A stronger final system should not depend on only one signal.

Potential signals:

    Eye closure duration
    Blink frequency
    EAR trend
    Yawning frequency
    MAR duration
    Head tilt duration
    Head orientation

Conceptually:

    Drowsiness Score =
        weighted eye signal
        + weighted yawn signal
        + weighted head signal

The exact weights should NOT be invented blindly.

They should be tuned through testing and evaluation data.

The goal is to reduce false alarms.

For example:

    Short blink
        -> normal

    Long eye closure
        -> strong drowsiness evidence

    Yawn alone
        -> warning/evidence

    Head tilt alone
        -> warning/evidence

    Long eye closure + yawn + abnormal head posture
        -> strong drowsiness evidence

16. KEY LESSONS FROM DEVELOPMENT
======================================================================

1. Always check the actual API provided by the installed library.
2. Do not assume an older MediaPipe interface exists.
3. Keep module interfaces consistent.
4. Test each module independently before integrating.
5. Use time-based conditions instead of single-frame triggers.
6. Calibrate eye thresholds for the individual user.
7. Normalize geometric angles before using them for thresholds.
8. Keep alarm execution separate from the camera loop.
9. Avoid opening multiple cameras unnecessarily.
10. Keep configuration values centralized where possible.
11. Detection thresholds are prototype values and should be evaluated.
12. A complete drowsiness system should use multiple signals rather
    than relying on only one measurement.
